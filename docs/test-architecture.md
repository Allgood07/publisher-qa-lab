# Архитектура масштабируемого набора проверок

`src/` — локальное приложение под тестом. При расширении набора с 9 до 15 сценариев вынесена повторяющаяся механика, затем те же сценарии разнесены по назначению. Сервис, конфигурация Playwright и workflow CI при переносе не менялись. Структура написана под этот проект; код и материалы другого проекта не перенесены.

| Слой | Ответственность |
| --- | --- |
| [`tests/support/fixtures/index.ts`](../tests/support/fixtures/index.ts) и [`server.ts`](../tests/support/fixtures/server.ts) | На каждый тест — новый loopback-процесс на порту, назначенном ОС. Каждый вызов `withVisitor` создаёт пустой браузерный контекст и закрывает его в `finally`. API-only тест не запрашивает браузер. |
| [`tests/support/pages/`](../tests/support/pages/) | `EditorPage` описывает действия автора; `ArticlePage` описывает общую разметку предпросмотра и публичной страницы. POM не содержит продуктовых ожиданий. |
| [`PublisherApi`](../tests/support/clients/publisher-api.ts) | Типизированный транспорт для локальных маршрутов. Возвращает фактический `APIResponse` и не следует редиректам; HTTP-статусы определяют сценарии. |
| [`tests/support/assertions.ts`](../tests/support/assertions.ts) | Узкий общий assertion-helper: видимость и точный DOM-текст заголовка и абзаца. Ожидаемые данные всегда передаёт spec; helper не решает, какая версия должна быть видна. |
| [`tests/support/layout.ts`](../tests/support/layout.ts) | Читает размеры документа и границы текста с учётом обрезающих предков. Допуск, ожидаемые значения и диагностические сообщения остаются в spec. |
| [`draftWithEncodedSize`](../tests/support/data/draft-with-encoded-size.ts) | Детерминированный генератор формы нужной длины в байтах после кодирования. Общая фабрика сущностей и случайные данные не нужны: тесты не делят хранилище. |

## Куда класть новый тест

| Назначение | Сценарий | Запуск слоя |
| --- | --- | --- |
| HTTP-контракт без браузера | [`tests/api/draft-validation.spec.ts`](../tests/api/draft-validation.spec.ts): отсутствующее поле даёт HTTP 400 | `npm test -- tests/api` — 7 тестов |
| Связь запроса с наблюдаемым UI-состоянием, без полного пользовательского маршрута | [`tests/integration/draft-size.spec.ts`](../tests/integration/draft-size.spec.ts): после HTTP 413 редактор и публичная страница сохраняют свои версии | `npm test -- tests/integration` — 5 тестов |
| Ключевое пользовательское действие через UI и наблюдаемый результат | [`tests/e2e/publication-lifecycle.spec.ts`](../tests/e2e/publication-lifecycle.spec.ts): после повторной публикации посетитель видит V2 | `npm test -- tests/e2e` — 3 теста |

Классификация зависит от проверяемого контракта, а не от подготовки: создание V1 через API не превращает E2E в API-тест. Все слои используют один Playwright-проект `chromium`; отдельный проект нужен, если появятся свои требования к окружению или запуску. Нет новых общих пакетов или фабрик.

Сценарии импортируют `test` и `expect` из `tests/support/fixtures/index.ts`. Фикстуры собирают POM и клиент; те не импортируют сценарии. В API-only запрос `publisherApi` не создаёт браузер. Серверный процесс принадлежит тесту, `request` и обычная `page` принадлежат Playwright, `withVisitor` владеет новым гостевым контекстом. Корневые `scripts/` — исполняемые проверки, а не технические helper-функции.

## Шесть проверок поверх пилота

- Отсутствующее `title` и отсутствующее `body`: два отдельных случая, HTTP 400.
- Ровно 16 384 байта тела `application/x-www-form-urlencoded`: HTTP 303, оба поля сохранены полностью. При 16 385 байтах — HTTP 413, наблюдаемые черновик и опубликованная версия не меняются. Это лимит закодированного запроса, не числа символов поля.
- Без черновика `GET /preview` и `POST /publish` возвращают 404, публичная страница остаётся недоступной.
- При обновлении посетитель видит V1, всё ещё V1 после сохранения V2 и оба поля V2 после явной повторной публикации.

## Фактические прогоны до разнесения по папкам

```sh
npm run typecheck
npx playwright test tests/draft-validation.spec.ts tests/draft-size.spec.ts tests/publication-lifecycle.spec.ts --project=chromium --workers=1 --retries=0
npm run test:cleanup
npm test -- --workers=2 --repeat-each=2 --reporter=list
npm test
```

Типы проверены; целевые файлы — `11 passed`, два воркера × два запуска — `30 passed`, штатно — `15 passed`. Дополнительно при `CI=true` на macOS и Node.js 22.23.5 прошли проверка типов, оба уровня очистки и `npm test` (`15 passed`). Команды локального набора и CI остались прежними; удалённый прогон этого расширения ещё не выполнялся.

`npm run test:cleanup` проверяет два разных уровня. Сначала намеренное исключение из callback фикстуры: PID исчез и TCP-порт отказал **пока процесс-владелец ещё работал**. Затем контрольное падение Playwright и внешняя проверка PID/порта после выхода раннера. В отдельной временной копии без явной остановки первая проверка упала на ожидании `ESRCH`: она не позволяет принять резервный IPC-disconnect за корректный teardown. Это учебный сбой, не дефект рабочего сервиса.

Первое независимое статическое ревью обнаружило, что исходная внешняя проверка не отличала явную остановку сервера фикстурой от выхода по IPC-disconnect. После добавления отдельной проверки исправление и границы assertion-helper согласованы повторным ревью; блокеров нет.

## Доработки по ревью POM

- [`published-snapshot.spec.ts`](../tests/e2e/published-snapshot.spec.ts): после сохранения V2 новый посетитель всё ещё видит V1; автор в предпросмотре видит точные данные V2; второе гостевое чтение после предпросмотра снова показывает V1. Оба гостевых чтения используют новые контексты.
- [`narrow-publication.spec.ts`](../tests/integration/narrow-publication.spec.ts): технические DOM-измерения перенесены в `layout.ts`, но ширина 360 px, элементы, пороги и допуск 1 CSS px остаются в сценарии.
- [`ArticlePage`](../tests/support/pages/article-page.ts) хранит один критерий локатора «Предпросмотр»; пилот требует присутствие внутри `main` в предпросмотре и отсутствие по всей публичной странице.

До разнесения по папкам `npm run typecheck` прошла. `npx playwright test tests/publish.spec.ts tests/published-snapshot.spec.ts tests/narrow-publication.spec.ts --project=chromium --workers=1 --retries=0` — `3 passed`; `npm test` — `15 passed`. Независимый Codex Reviewer проверил эти три доработки без правок и запусков: согласовано.

**Контрольные сбои только во временных копиях:** при подмене источника предпросмотра на `published ?? draft` старый набор дал `15 passed`, а усиленный сценарий — `1 failed`, ожидалась V2, получена V1. После выноса измерений вариант с обрезающим предком по-прежнему дал `1 failed` на правом крае заголовка. Вариант с меткой после `main` на публичной странице дал `1 failed` (`1` вместо `0`). Это доказательство чувствительности проверок, не новые дефекты рабочего сервиса.

## Приёмка структуры

- Сверка `npx playwright test --list --project=chromium --reporter=json` до и после: те же 15 уникальных названий (`7 API / 5 integration / 3 E2E`), без повторного обнаружения. Тела тестов и их ожидания совпали после исключения импортов и пустых строк при разделении двух файлов.
- Из чистого клона временного локального снимка (macOS, Node.js 22.23.5, `CI=true`): `npm ci`, `npm run typecheck`, `npx playwright install chromium` — успешно. До браузерной части запущено `PLAYWRIGHT_BROWSERS_PATH="$work/empty-browsers" npm test -- tests/api --reporter=list`, где `$work` — временная папка, а путь `empty-browsers` не существовал ни до, ни после команды. Все семь API-тестов прошли без установленного Chromium по этому пути.
- По одному точечному тесту каждого слоя — `1 passed` в каждом запуске. `npm run test:cleanup` — намеренное `1 failed` внутри Playwright, успешное подтверждение PID/TCP при живом владельце и после выхода раннера. Два воркера × два запуска — `30 passed`; последующий `npm test` — `15 passed`, HTML создан. Удалённый GitHub Actions этой ревизии пока не запускался.
- Две свежие Pi-сессии без подсказки путей нашли источник ожиданий, API-спек пропущенного заголовка и E2E-спек повторной публикации, объяснили выбор слоя и указали точечные команды. Сессии тесты не запускали; автор отдельно проверил оба фильтра через `--list` — по одному тесту. Независимый Codex Reviewer согласовал миграцию без блокеров; это статическое ревью, прогоны выполнил автор.
