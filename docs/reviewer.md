# Независимое ревью изменений

Запускать перед завершением значимого изменения контракта, тестовых ожиданий, изоляции, очистки, CI или `AGENTS.md`. Для Pi — отдельная сессия без истории реализации и без инструментов. Передать согласованный контракт, изменённые файлы (включая новые), минимальный контекст и фактические результаты команд. Отделять результаты штатных прогонов от намеренных падений. Не передавать секреты, настройки аккаунтов или полные логи.

## Задание ревьюеру

> Проверь реализацию против переданного контракта. Может ли тест пройти при неверном поведении? Ищи ошибки наблюдаемых ожиданий, изоляции, очистки и регрессии. Указывай файл и конкретный сценарий ошибки. Дай вердикт «согласовано» или «нужны изменения», отдели блокеры от неблокирующих замечаний. Файлы не изменяй; не выдавай переданные результаты за собственные прогоны. Не расширяй согласованный объём.

Автор исправляет блокеры, повторяет проверки и передаёт исправления на перепроверку. Если замечание требует изменить контракт или расширить задачу, это решение выносится отдельно. В итоговом отчёте разделить фактический прогон и статическое ревью. Этот процесс не зависит от CI и не заменяет проверки выполнения тестов.

## Как проверяем инструкции агента

Статическое ревью проверяет ссылки, границы и противоречия. Проверка навигации — отдельная процедура, не исключение из правил ревью. Свежая сессия получает задачу без имён файлов: по рабочим инструкциям она должна найти источник ожидания, нужный spec, минимальный слой и точечную команду. Для такой проверки разрешено чтение, но не правки и не запуск тестов.

До разнесения по папкам корневой `AGENTS.md` проверен в двух свежих сессиях Pi (`pi -p --mode json --no-session --no-extensions --no-mcp --no-skills --no-prompt-templates --no-themes --no-approve --tools read`). Обе начали с `docs/test-architecture.md` и перешли к нужному spec без подсказки путей:

- Повторная публикация: `tests/publication-lifecycle.spec.ts`, UI для сохранения и повторной публикации, API для подготовки V1, отдельный контекст посетителя. Указан один существующий тест на V1 → V1 → V2.
- Граница формы: `tests/draft-size.spec.ts`, API для закодированного тела в 16 385 байт и HTTP 413, UI для сверки прежних версий. Сессия отдельно указала, что вывод не относится к Site.pro.

Команды тестов сессии только предложили. Автор отдельно проверил обе команды через `--list`: каждая выбрала ровно один тест и не запустила его. Трассы проверены, но не сохранены в Git. После переноса те же принципы проверены с актуальными путями: `tests/api/draft-validation.spec.ts` для отсутствующего `title` и `tests/e2e/publication-lifecycle.spec.ts` для повторной публикации. Обе команды отдельно проверены через `--list`. Это проверка навигации в Pi, не свидетельство загрузки этого файла в другой клиент.
